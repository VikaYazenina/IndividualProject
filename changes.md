# Изменения в окончательной заявке и пользовательских сценариях


## Функциональные требования

1. Функциональное требование № 4 (расширенный поиск и фильтрация данных в веб-архиве)
Описание изменения:
Планировалось: поиск по ключевым словам и фильтрация по дате, источнику и т. п. в веб-архиве; стало: в веб-архиве реализованы поиск по заголовку, фильтр по категории и фильтры "только непрочитанные" / "только отложенные"; поиск по описанию, фильтры по источнику и дате публикации и постраничная выдача доступны через REST API.
Причина: при создании интерфейса приоритет был отдан работоспособному ядру (сбор, архив, рассылка), а страницы реализованы как серверные формы; элементы управления для дополнительных фильтров не были добавлены из-за нехватки времени, а сами фильтры реализованы в API.

2. Функциональное требование № 5 (система категорий / тэгов для источников)
Описание изменения:
Планировалось: категории и тэги, отдельный раздел "Категории", массовое изменение категории источников; стало: у источника одна категория (текстовое поле при добавлении), по которой фильтруется архив.
Причина: для решения задачи группировки источников достаточно одной категории, а тэги и отдельный раздел потребовали бы дополнительной таблицы связей и интерфейса; решено упростить реализацию.

3. Функциональное требование № 8 (экспорт результатов в различные форматы)
Описание изменения:
Планировалось: экспорт результатов в различные форматы; стало: экспорт всего архива пользователя в формате CSV.
Причина: CSV открывается в Excel и Google Таблицах и достаточен для анализа данных, а генерация других форматов (в том числе PDF) была отложена, чтобы уложиться в сроки.

4. Функциональное требование № 10 (новое: работа с аккаунтом)
Описание изменения:
Планировалось: в первоначальной заявке отсутствовало; стало: регистрация, вход и выход (пароль не короче 6 символов, хранится в виде хеша).
Причина: изначально данные были общими для всех посетителей, и любой видел чужие источники; для разделения данных пользователей потребовалась регистрация.

5. Функциональное требование № 11 (новое: раздел "Помощь")
Описание изменения:
Планировалось: в первоначальной заявке отсутствовало; стало: страница с описанием действий пользователя.
Причина: сервис используется без обучения, поэтому понадобилась встроенная справка по основным действиям.

## Пользовательские сценарии

6. Пользовательский сценарий № 1 (добавление RSS-источника)
Описание изменения:
Планировалось: кнопка "Добавить новый источник", выбор типа, ввод URL, автоматическое извлечение названия, окно с названием, кнопка "Сохранить источник"; стало: форма в разделе "Источники" с полями названия, адреса, типа и категории, название вводится вручную, проверка и сбор материалов запускаются сразу после добавления, результат показывается в сообщении.
Причина: интерфейс упрощён до серверных форм без всплывающих окон и предварительной загрузки ленты; проверка выполняется после сохранения.

7. Пользовательский сценарий № 2 (анализ активности)
Описание изменения:
Планировалось: график за 30 дней, диаграмма по категориям, топ-5 источников, экспорт статистики в PDF; стало: страница "Статистика" с числом собранных и прочитанных материалов за период (по умолчанию 30 дней) и распределением по источникам; PDF-экспорт отсутствует.
Причина: визуализации и генерация PDF потребовали бы дополнительных библиотек и времени; для оценки потребления достаточно числовых показателей.

8. Пользовательский сценарий № 3 (добавление веб-сайта без RSS)
Описание изменения:
Планировалось: кнопка "Проанализировать структуру", автоматические предложения CSS-селекторов для заголовка, даты и ссылки; стало: пользователь вводит селекторы блока материала, заголовка и ссылки вручную; дата публикации не извлекается.
Причина: автоматический анализ структуры страницы сложен в реализации, а использование ИИ-агентов, предложенное экспертом, было отклонено из-за отсутствия опыта и времени на обучение.

9. Пользовательский сценарий № 4 (создание персональной категории источников)
Описание изменения:
Планировалось: раздел "Категории", создание категории, массовое изменение категории у выбранных источников; стало: категория вводится при добавлении источника, а в архиве есть фильтр по категории.
Причина: следствие упрощения функционального требования № 5.

10. Пользовательский сценарий № 5 (запуск принудительного сбора материалов)
Описание изменения:
Планировалось: общая кнопка "Запустить сбор сейчас" с подтверждением, индикатором выполнения и окном "Сбор завершен"; стало: ручная проверка отдельного источника кнопкой у источника с итоговым сообщением; добавлены отключение и удаление источника.
Причина: проверка одного источника выполняется быстро и не требует индикатора выполнения и окна подтверждения; фоновый обход всех источников выполняет планировщик.

11. Пользовательский сценарий № 6 (поиск статей в архиве по ключевым словам)
Описание изменения:
Планировалось: поиск по заголовкам и описаниям, фильтр "Только за последний месяц", сообщение "По вашему запросу ничего не найдено"; стало: поиск по заголовкам, фильтры по категории и статусам, при отсутствии результатов показывается пустой список; фильтр по дате доступен только через API.
Причина: следствие изменения функционального требования № 4.

12. Пользовательский сценарий № 7 (экспорт подборки статей)
Описание изменения:
Планировалось: выбор статей галочками, выбор формата и полей файла; стало: ссылка "Экспорт CSV" в меню скачивает весь архив пользователя с фиксированным набором полей.
Причина: следствие изменения функционального требования № 8; выбор формата, статей и полей не реализован ради упрощения.

13. Пользовательский сценарий № 8 (формирование рассылки email-дайджеста)
Описание изменения:
Планировалось: раздел "Настройки" с выбором времени отправки, часового пояса, переключателем отложенного прочтения и лимитом статей; стало: дайджест отправляется раз в день по расписанию планировщика, лимит 50 материалов за письмо задан в коде, отложенное прочтение включается кнопкой у каждого материала, письмо можно отправить вручную кнопкой "Отправить дайджест сейчас".
Причина: пользовательские настройки потребовали бы отдельной таблицы и страницы настроек; для первой версии выбран единый режим рассылки, а настройки вынесены в планы развития.

14. Пользовательский сценарий № 9 (новый: работа с аккаунтом)
Описание изменения:
Планировалось: в первоначальных сценариях отсутствовал; стало: регистрация, вход и выход.
Причина: добавлено вместе с функциональным требованием № 10.

15. Пользовательский сценарий № 10 (новый: отложенное прочтение и отметка "прочитано")
Описание изменения:
Планировалось: в первоначальных сценариях отсутствовал; стало: отдельный сценарий для кнопок "Прочитано" и "Отложить".
Причина: в первоначальных сценариях эти действия были только частью настроек рассылки.

16. Пользовательский сценарий № 11 (новый: раздел "Помощь")
Описание изменения:
Планировалось: в первоначальных сценариях отсутствовал; стало: страница "Помощь".

## Прочие изменения в заявке

17. Раздел "Инструменты разработки, информация о БД"
Описание изменения:
Планировалось: PostgreSQL, Celery, Redis, Docker Compose, Playwright, Sentry, хостинг Selectel/Timeweb; стало: SQLite, APScheduler, Pytest и Ruff, Docker, GitHub Actions, хостинг Amvera.
Причина: для первого опыта разработки подобный набор был избыточен; SQLite и APScheduler проще в настройке и работают в одном процессе.
